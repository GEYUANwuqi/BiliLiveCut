# 任务执行与结果发布

Web 长耗时操作由组合入口 `app/web/services/background_jobs.py` 注册领域处理器。任务管理器位于 `app/jobs/manager.py`，只负责登记、调度、取消和恢复；持久化位于 `app/db/job_store.py`。公开记录与执行代次契约位于 `app/jobs/contracts.py`，领域处理器通过 `JobContext` 报告进度及提交结果。

## 登记与状态

去重键以用户和操作类型为作用域。登记在 SQLite 写事务中检查活动记录；相同键、不同请求会被拒绝，不会返回其他用户的任务。重复请求仍可获得已经登记的同一操作。

每次执行携带不可变的作业 ID 和 attempt。进度、结果和失败写入都校验当前代次；旧执行不能覆盖重试后的状态。已成功的结果不能改为取消，终态之后的进度也不能写回。

安全作业在异常重启后以新代次恢复；已请求取消的作业结算为取消。中断的上传保留人工核对提示，不自动重放外部操作。手动重试须等待上一次执行退出。

## 本地结果的提交点

领域先完成耗时计算，再进入 `JobContext.result_transaction()`。该事务在首次读取前取得写锁，验证作业仍在当前 running 代次；领域在同一 Session 写入正式结果，最后调用 `context.complete(db, result)`。退出时缺少成功终态会回滚整个事务。

- 本地录播导入：场次、分段、弹幕、流水线任务、导入结果和作业成功共同提交。
- 人工出片与审核重渲染：先准备主视频、派生版本及文案草稿，再复验候选、审核输入和流水线租约；成片引用、候选状态、关联流水线状态与作业成功共同提交。
- 合集：复验主题、事件关联、审核输入及来源成片后，共同发布合集版本、主题状态、候选状态与作业成功。

取消请求和成功发布使用同一数据库写锁。取消先提交则后续发布被拒绝；成功先提交则取消返回操作已经结束。人工审批本身是已经确认的输入行为，取消媒体计算不会撤销审批记录。

渲染文件使用每次执行独占的名称，重试不会覆盖已有版本。草稿没有正式数据库引用；计算失败清理本次声明的输出，发布失败先检查正式引用再清理。文件系统和 SQLite 不具备共同事务，进程在文件生成后突然退出仍可能留下无引用文件；这类文件不作为成功结果，不能据此重发上传。

上传等外部效果不具有本地事务原子性。远端状态由上传领域核对，任务成功只引用已经确认的结果；中断和未知结果保持明确诊断。

## 架构检查

`python scripts/check_architecture.py` 检查已经声明的任务层依赖方向，禁止任务管理器、任务契约及任务存储反向依赖 Web 或具体领域。检查器本身有反例测试，覆盖局部导入、相对导入和缺失模块。

导入检查不代替事务、线程或进程行为验证。`tests/integration/test_job_transactions.py` 使用真实 SQLite 连接验证发布与取消竞争、原子回滚、代次隔离和并发去重；媒体集成测试继续验证真实导入、字幕、派生版本及审核调用链。
